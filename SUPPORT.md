# Support

This repository is an open-source architecture framework and local validation toolset. It does not
provide a support contract.

## Questions that fit this repository

Use the relevant [GitHub issue form](https://github.com/aramsmith/agentic-architecture-v2/issues/new/choose)
for:

- clean-clone setup and documented command failures;
- reproducible validator, renderer, or synthetic Contoso smoke defects;
- schema, lifecycle, profile, or skill design proposals;
- unclear, incorrect, missing, or inaccessible documentation.

Search existing issues before filing a new one.

Version support and verified platforms are defined in
[`docs/compatibility.md`](docs/compatibility.md).

## Boundaries

Repository maintainers cannot provide:

- legal, regulatory, security, privacy, or compliance certification;
- production deployment approval or authorisation;
- warranties, service levels, or guaranteed response times;
- support for GitHub Copilot, a model provider, Azure, or another vendor's product;
- customer-specific architecture decisions, risk acceptance, or human approval;
- review of confidential customer evidence through public GitHub content.

The human architect and the relevant organisation remain accountable for architecture decisions,
approvals, deployment, testing, and production operation.

## Choose the right route

- **Bug:** use the bug report form.
- **Framework or design change:** use the proposal form.
- **Documentation or usability:** use the documentation form.
- **Security vulnerability:** do not open an issue; follow [`SECURITY.md`](SECURITY.md).
- **Code of conduct concern:** use the GitHub reporting route in
  [`CODE_OF_CONDUCT.md`](CODE_OF_CONDUCT.md).

## Safe diagnostic information

It is useful to share:

- operating system and Node.js/npm versions;
- affected commit, tag, file path, or schema version;
- the exact command and sanitised error output;
- expected and observed behaviour;
- a minimal synthetic reproduction;
- which documented checks pass or fail.

Do not share credentials, tokens, keys, customer names, real case folders, architecture evidence,
personal or regulated data, subscription or tenant details, private URLs, or unredacted logs. Replace
them with synthetic values before posting.
