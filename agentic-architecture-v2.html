Start-up manual

Five stages. Each one is a safe place to stop.

Stage one needs nothing but Node.js — no GitHub Copilot, no Azure, no credentials, no key. Prove the framework is sound before committing to anything.

01

Install and prove it works

Offline · ~10 min

Prerequisites: Git, Node.js 22 or later, npm, Windows PowerShell.

> git clone https://github.com/aramsmith/agentic-architecture-v2.git
> Set-Location .\agentic-architecture-v2
> npm ci --no-audit --no-fund
> npm run validate -- --framework-only
> npm run smoke:contoso -- --keep-output .\.aff-smoke\contoso-review

The framework validates, every offline assertion passes, and the report records zero live model calls and zero Azure actions. The generated overview labels its approval as synthetic test evidence — because no human made it.

Safe stop point. This proves internal consistency. It does not prove model quality, Azure access, deployment, runtime behaviour, or real human approval.
02

Create your approval identity

Once, ever

This is the key that signs every phase decision you make.

> npm run identity:create

You choose a label — a role such as Accountable architect keeps a personal name out of case folders — and a passphrase. The passphrase is never written to disk and cannot be recovered. It is the one secret an agent sharing your machine cannot read.

Creating the key also switches on a policy for this machine: a real human decision must be signed. Skip this stage and approvals still work, but they read self-asserted.

03

Connect GitHub Copilot

For real cases

Open Copilot CLI from the repository root, then confirm discovery:

  1. /agent — confirm AFF-0-coordinator is listed.
  2. /skills list — confirm grill-me and render-case-html.

Agents load from .github/agents/ and skills from .github/skills/, the locations GitHub documents for custom agents and project skills.

Safe stop point. Discovery proves packaging only — not model quality, reviewer convergence, or production fitness.
04

Start your first case

Per engagement
> New-Item -ItemType Directory .\cases\<case-name>\input

Add the architecture brief and supporting evidence, then invoke AFF-0-coordinator. Do not start with AFF-1 — Phase 0 establishes the source inventory, model plan, shared records, interview preparation, and review routing.

Never commit case data. Case folders stay local and are ignored by Git. Never include credentials, tokens, or unnecessary personal or regulated data.
05

Approve each phase, one at a time

Repeat to Phase 6
  1. Read the phase document, both reviewer records, decisions, and residual risks.
  2. Decide — in your own terminal, with no agent session running.
  3. Confirm the case still holds, then continue.
> npm run approve -- --case cases\<case-name> --phase 0
> npm run validate -- --case cases\<case-name>

The approval command prints the artifact hashes and both final verdicts, then asks you to approve, reject, or cancel, and finally for your passphrase. It refuses to offer a decision the evidence does not support. A phase cannot be entered, evidenced, or approved until its predecessor holds an approved decision.

Never type your passphrase into an agent conversation. An agent that asks for it is phishing you, whatever its intent.

Phase assurance

Independent challenge. Shared evidence. Human authority.

Every invoked phase runs this sequence. Any material change invalidates the reviews that covered the earlier version, and the gate reopens.

  1. Phase agent — creates the candidate and records its hashes.
  2. Rubber Duck Reviewer — challenges logic and unsupported claims, on a different model.
  3. Phase agent — resolves accepted findings.
  4. Security and Compliance Reviewer — assures security, privacy, sovereignty, compliance.
  5. Phase agent — resolves accepted findings again.
  6. Both reviewers — re-review until their final verdicts cover identical, unchanged hashes.
  7. You — read the evidence and sign the decision with your key. Nothing proceeds until you do.

What an approval actually proves

The validator derives the mode from the evidence — never from what the record claims about itself.

ModeWhat it meansHow it is reached
human-verifiedSigned by your approval key and unchanged since.You ran the approval command and unlocked your key.
self-assertedRecorded without verification of who decided.A decision on a machine holding no key. Rejected where a key exists.
syntheticGenerated by the offline harness. No human decision was made.Produced only by the Contoso smoke test, which cannot emit anything else.
Stated plainly. Verification is not access control. An agent may still write an approval file — it simply cannot produce a valid signature without a passphrase that is never stored. And a human who types that passphrase because an agent asked has delegated their authority, which is not forgery.

Operating principles

What the framework refuses to do.

Enforced by a deterministic validator, not by agent good behaviour.

Human-final governance

Agents prepare and challenge; you decide and sign. On a machine holding an approval key, an unsigned decision is rejected.

Enforced phase order

A phase cannot be entered, evidenced, or approved until its predecessor holds an approved decision.

Independent review

The rubber duck must run on a different model from the phase agent. If none is available, the gate stays shut.

Least privilege

Every agent declares its capabilities. Reviewers may never run commands or drive other agents.

No invented facts

Unknowns become explicit decisions, blockers, or owned assumptions with a named human owner.

Safe rendering

Case HTML is generated deterministically, never authored by a model. Remote content and unsafe SVG are rejected.

Azure-ready, never reckless

Bicep-first, parameterised environments, private databases. Phase 5 validates locally and never deploys.

No stored credentials

Interactive sign-in or an approved managed identity. GitHub OIDC is outside this solution.

Case data never leaves your machine

Real case folders are ignored by Git by design. Only the template and the synthetic Contoso case live in the repository. Keep customer material local, and never commit or push it.
