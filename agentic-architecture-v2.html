The architecture ring

The human architect stays at the centre.

Standard phases move from brief to board narrative. The Rubber Duck Reviewer challenges the reasoning; the Security and Compliance Reviewer challenges the controls. Deployment and runtime testing remain optional.

Human-final governance

No phase progresses until both reviewers cover the same artifact hashes and the human approves.

Independent challenge

The Rubber Duck Reviewer uses a different model. The Security and Compliance Reviewer derives obligations from case evidence.

Compact, traceable outputs

Each phase produces one authoritative Markdown document, safe HTML, and only essential evidence.

Azure-ready, never reckless

Bicep-first implementation, private databases, no stored deployment credentials, and no automatic deployment.

Fail closed

Missing evidence, model independence, scope, approval, or safe rendering stops the lifecycle.

Short manual

Start with a brief. Start with AFF-0.

The operator only needs to prepare the case input, choose the models, and keep control of each gate.

Case entrypoint

Place the brief and evidence in the case input folder. Do not include credentials or unnecessary personal data.

cases/<case-name>/input/
Invoke:
AFF-0-coordinator
1

Choose models

Select each agent's model in Copilot. AFF-A must use an explicit model different from the phase owner.

2

Create the case

Copy the architecture brief template or add your own brief and supporting evidence beneath the input folder.

3

Invoke AFF-0

AFF-0 inventories and normalises inputs, initialises the model plan and records, and prepares—not conducts—the interview.

4

Review and approve

Read the phase output, Rubber Duck review, Security and Compliance review, decisions, and residual risks. Approve only when both reviews cover the same hashes.

5

Progress one phase at a time

Continue through AFF-6. Invoke AFF-7 and AFF-8 separately only when deployment or runtime assurance is genuinely required.

Practise with the included example case

Contoso is Microsoft's familiar fictitious company name used in examples. Contoso Permit Services and this architecture case are entirely synthetic and exist solely for testing this solution. Before using real customer information, run AFF-0 against cases/contoso-permit-services/input/. This lets you verify input handling, model choices, reviewer sequencing, human approval, and the opening requirements interview without Azure access, credentials, deployment, or live testing.
